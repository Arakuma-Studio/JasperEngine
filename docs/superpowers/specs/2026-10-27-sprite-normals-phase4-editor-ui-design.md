# Sprite Normals Phase 4: Editor UI (window, Project window, Inspector, regenerate)

Status: binding for the Phase 4 implementer (wave 2, one implementer in its own worktree, in parallel with Phase 3).
Conforms to `2026-10-27-sprite-normals-contract.md` (the contract wins on any conflict). Phase 2 defines the exact
headers of the core, media, preview, session and apply APIs (contract section 8); this spec names them by their
contract names and never redefines them. Wherever this spec says "the session", "the worker", "renderLit",
"metrics/assess", "apply" or "the recipe reader", read "the Phase 2 function of that contract name".

## 1. Goal and non-goals

Goal: a person who has a pixel-art sprite gets a correct normal map in at most two clicks, sees it lit by a light
they can drag before anything is written, and gets it assigned to the sprite with the right sampler settings. When
the source art changes they are told, and can regenerate in one click (or let the editor do it).

Entry points (all reach the same window model):

| Entry | What happens |
|---|---|
| Window > Sprite Normal Map | Opens the window (empty, or as last left) |
| Project window, right-click an image > "Generate Normal Map..." | Window opened with that image as the source |
| Project window, N > 1 images selected > "Generate Normal Maps (N)..." | Window opened in batch mode with the N images |
| Project window, right-click a generated output > "Edit Normal Map..." | Window opened with the output's recipe restored |
| Project window, right-click a generated output (or a source that has one) > "Regenerate Normal Map" | Regenerates from the recipe at once, no window, one Project undo step |
| Inspector, Mesh Renderer > Normal Texture row, wand button | Click: window opened on the row's Base Texture with Assign on; Shift-click: generate (or regenerate from the recipe) and assign at once |
| Inspector, Sprite > Sprite Frames, "Normal Map..." button | Window opened with the GameObject as the source (its texture and frames), Assign on |
| Inspector, generated output (or its source) clicked in the Project window | The new image asset view (section 6) |
| MCP `focus_window {window: "sprite_normals"}` | Opens and focuses the window |

Non-goals (this phase): painting/correction brushes (Phase 5 adds them to this window: leave the left-click on the
canvas free in every mode except the eyedropper, section 3.5); the MCP tool and CLI (Phase 3); changing Project
window sort order (a generated file is not moved next to its source); image import settings for non-generated
images (the Inspector keeps showing the scene selection for plain images, section 6.1).

## 3. The Sprite Normal Map window

### 3.1 Model

The window holds one session `Spec` per source (single mode: one; batch mode: N), one shared settings set (the
contract section 3 settings), the assign target, the preview state, and at most one running worker. All model
operations are the scripted API (3.8); buttons, shortcuts, the Project window, the Inspector, MCP `focus_window` and
the tests call only that API.

Live regeneration: any change to the settings, the frames, the source or the current batch item schedules a run
150 ms after the last change (debounce, measured with `ImGui::GetTime()`; the test access can advance it). A newer
change cancels the running worker and restarts it. The preview keeps showing the previous result, labelled
"Updating..." in the canvas corner, until the new result arrives (no flicker to empty). Nothing is written until
Save. A source of more than 1,048,576 pixels (or more than 64 frames) does not regenerate live: the Generate button
appears instead (section 3.4) and the stale label reads "Settings changed: Generate to update".

### 3.2 Layout

`ImGui::Begin("Sprite Normal Map")`, default size 64 x 40 font-sizes on first use, docked by default as a tab in the
centre node next to Scene/Game/Texture Synthesis (`App` dock builder, and Reset Layout). A two-column resizable table
`##layout` exactly like Texture Synthesis: left column fixed at 23 font-sizes wide (settings child `##settings` that
scrolls, with a pinned footer for the action buttons, progress and status measured as Texture Synthesis does), right
column stretches (preview child `##preview`, no scrollbar, no mouse-wheel scroll).

Left column, top to bottom (section headers with `ImGui::SeparatorText`):

1. Notices (info lines, warning colour, `ICON_FA_CIRCLE_INFO`): recipe notes ("Restored from X; its source is
   unchanged, so Regenerate reproduces it." / "hero.png changed since this normal map was generated.").
2. **Source** (single mode) or **Sources** (batch mode), 3.3.
3. **Frames**, 3.3.
4. **Preset** + the four main sliders, 3.4.
5. **Advanced** foldout (`Theme::foldoutHeader`, closed by default), 3.4.
6. **Output**, 3.4.
7. **Warnings** rows, 3.6 (only when there are any).

Footer (pinned): primary button, secondary button, progress, status (3.7).

Right column: toolbar row (wraps when narrow, as Texture Synthesis' `next()` helper does), canvas filling the rest
minus 3.2 text lines, metrics/assessment lines under it (3.5).

### 3.4 Settings and Output sections

Preset row: `segmentedButtons("##preset", ...)` (copy Physics Placement's helper into the window's anonymous

- Soft: "Gentle relief for painterly art (strength 1, detail 2, smoothing 1)"

- Crisp: "Small characters: keeps 1 px features (smoothing 0.6)"

### 3.5 Preview

Toolbar (left to right; every control has a UI probe name `spriteNormals.<id>` via `UIProbe::item`):

| Control | Id | Values | Shortcut |
|---|---|---|---|
| View | radio `Color` / `Normal` / `Lit` / `Split` | default `Lit` | 1 / 2 / 3 / 4 |
| Frame | combo `##frame` "All" / "Frame 1" ... (only with > 1 cell), plus `<` `>` buttons | default All | `,` / `.` |
| Play | toggle button `ICON_FA_PLAY`/`ICON_FA_PAUSE` (only with > 1 cell) | off | Space |
| Orbit | toggle `Orbit` | off | O |
| Grid | checkbox `Grid` (only with cells) | on | G |
| Fit | button `Fit` + zoom text "600%" | - | F (fit), 0 (100%) |

Light row (second toolbar row, Lit and Split views only): `Height` drag float (1..4096 px, default per below,
"Height of the light above the sprite, in pixels (the Light 2D's Height). Mouse wheel over the canvas with Shift
changes it"), `Colour` ColorEdit3 no inputs (default white), `Ambient` slider 0..1 (default 0.25, "Light everywhere,
like the scene's 2D ambient"), `Range` drag float (1..8192 px, default 3 x the larger cell side), `Reset light` small
button.

Light defaults for a source: position = the cell centre offset by (-0.5, -0.5) x the larger cell side (up-left),
height = clamp(0.6 x the larger cell side, 4, 512), range 3 x the larger cell side, falloff 1, intensity 1, ambient
0.25. Light coordinates are image pixels relative to the shown cell's top-left (All view: the image's).

Canvas (`InvisibleButton("##canvas")`, the Texture Synthesis `drawCanvas` structure):
- Background: the Image Viewer checkerboard (`ImageViewerWindow.cpp` 341-361 pattern) under the image so alpha shows.
- Zoom is screen pixels per image pixel. Fit = the largest whole number that fits (a fraction below 1 only when the
  image is larger than the canvas). Mouse wheel steps through 0.25, 0.5, 1, 2, 3, 4, 6, 8, 12, 16, 24, 32, 48, 64
  about the cursor. Right or middle drag pans; double-click left = Fit. Images are drawn with nearest magnification
  (`updateGpuImage` with `TextureFilter::NEAREST` mag, copied from Texture Synthesis including `retire()` and
  `releaseRetired()` one frame later).
- Color: the source (or the colour atlas for an animation). Normal: the normal map RGB with alpha. Lit:
  `renderLit(normal, colour, light)` (the contract's engine-exact formula). Split: Color left, Lit right, a vertical
  divider (2 px, accent colour, `InvisibleButton` handle 8 px wide, cursor `ResizeEW`) at 50% by default, dragged
  anywhere; its position persists for the window session.
- Lit/Split: the light is a 10 px disc with a soft halo drawn at its position; left-drag anywhere on the canvas (not
  in eyedropper mode) moves the light (the cursor shows `ICON_FA_LIGHTBULB` hint text "Drag: move the light"); a
  plain mouse wheel zooms; Shift + wheel changes the light height by x1.1 per notch.
- Lit rendering is recomputed only when the result, the light, the frame or the view changes, throttled to 30 Hz;
  in All view of an image above 1,048,576 pixels only the visible part at the current zoom is rendered.
- Orbit: the light circles the shown cell's centre at radius 0.6 x the larger cell side, one turn per 4 s, at the
  current height; dragging the light stops Orbit.
- Play: steps cells with the result's frame delays (`delays_ms`; sheets without delays: 100 ms), loops, shows the
  frame number in the corner; in All view Play switches the view to the first frame. Play and Orbit request redraws
  every frame while on (`Backend::getApp().requestRedraw()`).
- Grid overlay (cells): the Texture Slicer dialog's overlay (green rects + index numbers, `TextureSlicerToolDialog.cpp`
  323-375), in All view.
- Eyedropper: while a region's pick toggle is on, the cursor is a crosshair over the image, a left click adds the
  clicked pixel's colour (from the source, alpha > threshold only; clicking an empty pixel says "That pixel is empty")
  to that region; Alt + left click picks into the most recently edited region from any view (creating region 1 when
  there is none); Esc ends picking.
- Labels drawn in the canvas corner: the view name, "Updating..." while a run is live, "Settings changed" when stale.
- Empty state: "Pick a source image (or right-click an image in the Project window > Generate Normal Map...)".

Metrics lines (under the canvas): `W x H, N frames, radius R | <assess lines joined by " | ">`, the hint in warning
colour when not "Looks fine.", the result's warnings in warning colour, and after a save "Saved: <first path> (+N
more)".

### 3.6 Warnings rows (left column, with one-click fixes)

Rows are recomputed at most twice a second and after every change. Each row: warning (or error) colour text, then
fix buttons on the same line when room (else the next line). All fixes are undoable (scene fixes one scene undo step
each, through `CommandHandle::get(sceneId)->addCommand(...)` with `setNoMerge()`).

| Kind | Condition | Text | Fixes |
|---|---|---|---|
| `no_light` | an assign target exists, its scene has no enabled Light 2D | "No Light 2D in this scene: normal maps need a light." | `Create Light 2D` (CreateEntityCmd POINT_LIGHT_2D named "Light 2D", positioned at the target's world position + (-0.5, +0.5) x the sprite size, height 64, one scene undo step; then selected) |
| `no_light_height` | lights exist but `lightsRespondToNormals(scene)` is false | "No Light 2D in this scene has Height > 0, so normal maps won't show." | `Set Height 64` (every enabled Light 2D with height 0 gets 64: one MultiPropertyCmd), `Select Lights` |
| `filter_mismatch` | the target's normal texture is set and its min/mag filter or wrap differs from the base texture's | "The Normal Texture is filtered differently from the Base Texture (pixels will smear at edges)." | `Match Base Texture` |
| `size_mismatch` | the target's base texture size differs from the planned normal map size (error colour) | "Base Texture is W x H but this normal map would be w x h: they must match." | `Use Base Texture` (source := the base texture) |
| `directx` | `directx` on and an assign target exists | "DirectX green: this engine reads OpenGL. Lights will look upside down." | `Switch to OpenGL` |
| `shader_ignores_normals` | the target material's shader is a library/custom shader that does not sample a normal map (Phase 1's manifest query) | "This material's shader ignores normal maps." | none |
| `output_exists` | a planned output exists (single mode) | "hero_normal.png exists: Save replaces it (undo puts it back)." | none (the Save confirm handles it) |
| `source_changed` | the loaded source's mtime/size changed on disk since it was read | "The source changed on disk." | `Reload` |
| session problems | `checkSpec` problems | the problem text (error colour) | none (Save disabled) |

### 3.7 Actions and status (footer)

- Primary button (accent colour, 1.4 x frame height, half width): `ICON_FA_FLOPPY_DISK " Save"` or
  `" Save & Assign"` when Assign is checked; batch mode `" Save All (N)"`. Disabled with the reason as tooltip: no
  result yet ("Wait for the preview"), stale ("Updating: wait for the preview"), problems ("Fix the problems listed
  above first"), scene playing and Assign on ("Stop the scene to assign the normal map").
- Secondary button (half width): `ICON_FA_STOP " Cancel"` while a run is live; otherwise `ICON_FA_PLAY " Generate"`
  when live regeneration is off for this source (3.1), else `ICON_FA_ROTATE " Regenerate"` (forces a run now).
- Save flow (single): the session writes the outputs of the shown result (never re-generating when the result
  matches the settings) as one Project undo step; existing outputs ask first through
  `registerConfirmAlert("Replace Files?", "These files exist and would be replaced:\n  <list>\n\nReplace them?
  (Undo in the Project window puts them back.)")`; then if Assign is on, apply runs as one Scene undo step on the
  target. Then the Project window reveals the normal map (`revealAsset`) and refreshes its thumbnail
  (`requestThumbnailGeneration(path, true)`). Status: "Saved hero_normal.png (Project undo) and assigned to Hero
  (Scene undo)." / "Saved 3 files as one undo step.".
- Save All (batch): runs every checked item that has no current result on the worker one after another (progress bar
  "Item 3 of 8", Cancel stops and writes nothing), then writes all files in ONE `writeOutputsUndoable` call, one
  confirm listing every existing file.
- Progress: `ImGui::ProgressBar` while a run lasts more than 0.3 s ("Frame 3 of 24" / "Item 3 of 8" from the
  worker's progress), errors of a failed run in error colour, then the status line.

### 3.8 Scripted API (`SpriteNormalsWindow`)

```cpp
class SpriteNormalsWindow {
    friend struct SpriteNormalsWindowTestAccess;
public:
    static constexpr const char* WINDOW_NAME = "Sprite Normal Map";
    enum class View { Color, Normal, Lit, Split };
    struct WarningRow { std::string kind; std::string text; bool error = false; std::vector<std::string> fixes; };

    explicit SpriteNormalsWindow(Project* project);
    ~SpriteNormalsWindow();                       // cancels a live run
    void show();                                  // once a frame (also ticks Play/Orbit/debounce)
    void open(); void setOpen(bool open); bool isOpen() const;
    void resetForProjectSwitch();                 // cancel, forget sources, results, targets, GPU images

    // entry points (absolute or project-relative paths); false + error when nothing usable
    bool openSources(const std::vector<std::filesystem::path>& images, std::string& error);   // 1 = single, >1 = batch
    bool openRecipe(const std::filesystem::path& generatedPng, std::string& error);           // "Edit Normal Map..."
    bool openForEntity(uint32_t sceneId, Entity entity, unsigned submesh, bool now, std::string& error);
    // Regenerate Normal Map: from the output's recipe, written over it (one Project undo step), no window
    static bool regenerateFromRecipe(Project* project, const std::filesystem::path& generatedPng,
                                     std::vector<std::string>& written, std::string& error);

    // settings (the shared set) and the current item's spec
    void setSettings(const spritenormals::Settings& s);         // Phase 2's settings type
    const spritenormals::Settings& getSettings() const;
    void setPreset(spritenormals::Preset p);
    void setFrames(const spritenormals::FramesSpec& f);          // Phase 2's frames type
    void setOutput(const std::string& projectRelative);          // "" = default
    void setHeightMap(bool on);
    const spritenormals::Spec& currentSpec() const;
    void setAssignTarget(uint32_t sceneId, Entity entity, unsigned submesh);
    void clearAssignTarget();
    void setAssign(bool on);

    // batch
    size_t itemCount() const; size_t currentItem() const; void selectItem(size_t i);
    void setItemChecked(size_t i, bool checked); bool isItemChecked(size_t i) const;

    // running
    bool regenerate(std::string& error);          // a run now (no debounce)
    void cancel();
    bool isRunning() const; bool hasResult() const; bool isStale() const;
    // Save / Save & Assign (assign = the checkbox's value); batch: Save All
    bool save(bool overwrite, std::vector<std::string>& written, std::string& error);

    // preview
    void setView(View v); View getView() const;
    void setLight(float x, float y, float height); void setLightColour(const Vector3& c); void setAmbient(float a);
    void setFrame(int index);                     // -1 = All
    void setPlaying(bool on); void setOrbit(bool on);
    bool pickRegionColour(int region, int px, int py, std::string& error);   // the eyedropper's click

    // warnings
    const std::vector<WarningRow>& getWarnings() const;
    bool applyFix(const std::string& kind, const std::string& fix, std::string& error);
};
```

`SpriteNormalsWindowTestAccess` (declared in the header as a friend, defined only in the test) exposes: the worker,
the debounce clock (`advance(seconds)`), the lit preview image (CPU, RGBA8), the GPU images' validity, the light
state, the split position, the warnings refresh (`refreshWarningsNow`), the confirm-dialog callback of the last
`registerConfirmAlert` (to accept it headless), and `drawFrame()` (one headless ImGui frame of `show()`).

### 3.9 Persistence (workspace.yaml)

`Project` gains `SpriteNormalsWindowSettings spriteNormalsSettings` (struct in `SpriteNormalsWindow.h`'s namespace
or a small header `editor/window/SpriteNormalsWindowSettings.h`) saved under the workspace key `spriteNormals` with
`Stream::encodeSpriteNormalsSettings` / `decodeSpriteNormalsSettings` (the `physicsPlacement` pattern, read in its own
`readSection("the Sprite Normal Map settings", ...)`): the last used settings (preset + every override + regions),
`view`, light height/colour/ambient, `orbit`, `grid`, `advancedOpen`, `autoRegenerate` (default false). Unknown or
invalid values fall back to defaults with the existing workspace warning path. "Last settings" (Shift-click) means

## 7. Staleness and auto-regenerate (`SpriteNormalsWatcher`)

- Owned by `Project` (or `App`, whichever ticks `refreshFbxImports`), ticked from the same per-frame place
  (`App.cpp` near 2793). Paused while any scene plays and while a project switch is in progress.
- Index: every `.png` under the project's assets carrying a `jasper.spritenormals` recipe, built off the main thread
  (a `std::future`, the FBX scan pattern) on project open and re-scanned at most every 5 s, incrementally by mtime and
  size. For each output: the recipe's source path and SHA-1. Source hashing (SHA-1 of the file) runs off the main
  thread and is cached by source path + mtime + size, so an unchanged source is never re-hashed.
- API: `bool isStale(const fs::path& output) const`, `bool sourceMissing(const fs::path& output) const`,
  `std::vector<fs::path> outputsOf(const fs::path& source) const`, `void invalidate(const fs::path&)` (after any
  write), `uint64_t revision() const` (the Project window re-reads badges when it grows).
- Auto-regenerate (opt-in per project, off by default): when an output becomes stale (source changed, not missing),
  regenerate it from its recipe on the worker and write it with the session's plain all-or-nothing writer (not an
  undo step, like an FBX reimport), keeping any Phase 5 paint layer the recipe carries; log
  `Out::info("Regenerated %s (%s changed)")`; failures `Out::warning`. At most one regeneration at a time; a change
  that arrives during a run re-queues. Outputs of a source changed within the last 1 s wait (editors writing in
  several steps).
