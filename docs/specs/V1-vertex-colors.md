# V1 — Vertex colors: storage, painting, selection, materials, bakes and runtime paint

Wave: authoring (spec-first). Owner stream: vertex colors. Analyst reports (reading only, 2026-11-15):
six external tools (section 4) and three readings of this codebase (data path, editor tooling,
MCP/Lua). Nothing was built or run for this spec; every "today" claim below was read in the code, and
the key citations were re-read on 2026-11-16.

## 1. Goal

A person or an agent can give any mesh in a scene vertex colors and see them: by brush, by selecting
exact vertices, faces or corners and setting their value, or by generating them (from a texture, AO,
curvature, gradients, noise, another mesh). The colors are stored per placed object, never by editing
the source model, and faces can have hard color edges on any mesh. Every use of vertex colors is
supported end to end: visible color (tint, unlit, baked lighting), masks that blend texture layers,
masks that drive PBR inputs, raw data channels for shaders (wind, flow, custom), and paint written by
gameplay at runtime. One operation engine serves the brush, the selection tools, the bakers, MCP and
Lua, so all of them mean the same thing and can be tested without a GPU.

## 2. Scope

**In scope**
- `engine/core/vertexcolor/`: the color data model (per vertex plus per-corner overrides), the
  `.vcolors` file, the operation engine, targets and filters, the vertex spatial index, bakers that
  need no editor (AO, curvature, gradient, noise, from texture, transfer).
- A new `VertexColorsComponent` ("Vertex Colors" in the Inspector) and its render path: a color
  stream bound per placed object, split vertices for hard edges, LODs, skinning, morphs, instancing.
- Scene view Draw Mode **Vertex Color** (RGB, R, G, B, A).
- Editor: the Vertex Paint window and scene tools (Select, Paint, Smooth, Fill, Gradient, Pick), mesh
  element selection (vertex, face, corner), the apply panel, palettes, "Colors on this mesh", masks,
  bake dialogs, Export as Model, Bake to Texture, undo, shortcuts.
- Materials: a **Vertex Color** section in the built-in Lit material (Tint / Masks / Off), the
  `library:vertex_blend` layer-blend shader, channel names shared by painter and material.
- Runtime: Lua `VertexColors` API including transient paint with hold and fade.
- MCP: `edit_mesh_colors`, `sample_mesh_colors`, `bake_mesh_colors`, the `vertex_color` draw mode,
  vertex color facts in `get_model_info`; guide section in `docs/mcp/guide/meshes.md`.

**Out of scope** (default decisions, not open questions)
- More than one color stream per mesh (`COLOR_1`, custom attribute streams). One RGBA stream; four
  channels is the contract. Recorded in section 9 as a later extension.
- Topology editing (subdivide, extrude, weld). Painting needs vertices; the UI warns about low density
  and points to model import or higher-segment primitives. No mesh editor is introduced.
- Render-target (UV-space texture) painting. Vertex colors only; Bake to Texture is a one-shot export.
- GPU or compute painting. All painting runs on the CPU (jobs); the GPU only draws (AGENTS.md).
- A shader graph (S90 reserves it; S11 excludes it). Vertex color reaches custom shaders through the
  existing `@require rawcolor` / `SURFACE_COLOR` path.
- Copying code from the reference tools (section 4): ideas only, reimplemented.

## 3. Current state

Abbreviations: **MC** `engine/core/component/MeshComponent.h`, **MS**
`engine/core/subsystem/MeshSystem.cpp`, **RS** `engine/core/subsystem/RenderSystem.cpp`, **SR**
`editor/render/SceneRender.cpp`, **SW** `editor/window/SceneWindow.cpp`.

**Mesh data.** Vertex layouts are data-driven: `AttributeType::COLOR` (`engine/core/render/Render.h:210-217`)
points at any named buffer with any data type (`engine/core/buffer/Attribute.h:17-25`); sokol formats
include UBYTE4N and HALF4 (`engine/renders/sokol/SokolObject.cpp:284-316`). `Submesh::hasVertexColor3/4`
(MC:420-421) are rescanned on every load (RS:3907-3970) and pick the shader variant. Generated
primitives carry float4 white color in their interleaved buffer (MS:768 and the other builders);
glTF meshes use pooled external buffers (`MeshComponent::eBuffers`, MC:541-545,
`engine/core/pool/MeshBufferPool.h`). Buffers default to IMMUTABLE; uploads are whole-buffer
(`updateMeshBuffers`, RS:10258-10292); a shared buffer whose bytes change gets its own pooled buffer
and, changed often, a private DYNAMIC one (RS:10312-10342).

**Model structure.** A Model's mesh-node child entities are generated by the loader and torn down on
reload (`ModelComponent::meshNodesMapping`, `engine/core/component/ModelComponent.h`). A component put
on such a child would not survive a reload: per-object data must live on the Model's entity and
address meshes by glTF node and primitive. Merge Static Meshes bakes nodes into one mesh
(`mergeStaticMeshes`).

**Import and cook.** glTF COLOR_0 is kept (MS:5871-5956; u8/u16 VEC3 widened to VEC4, MS:2942-2990);
FBX goes through `GlbBuilder` and writes float4 COLOR_0 (`editor/util/GlbBuilder.cpp:779`). The cook
(`editor/model/ModelCooker.h:4-19`) keeps node, mesh, primitive and accessor indices but welds and
reorders vertex data; lossy compression stores color as 8 bits. Model-backed meshes never save their
buffers (`editor/Stream.cpp:6064-6100`). **There is no per-instance vertex data override.**

**Shaders.** Built-in Lit always multiplies albedo (and alpha) by vertex color when the mesh has one
(`getVertexColor`, `engine/shaderlib/includes/pbr.glsl:13-24`; applied in `getBaseColor`). Variant bits
`Vc3`/`Vc4` (`engine/core/shader/ShaderVariantCompiler.cpp:380-381`). Library shaders opt in with
`@feature VERTEX_COLOR` (unlit, simple_lit, vertex_lit, decal, …) or read raw values with
`@require rawcolor` (`includes/surface_vs.glsl`); `library/vertex_color.frag` exists. Data uses
today: foliage wind mask from R (`includes/foliage_wind.glsl`), river flow in RG/B
(`engine/core/spline/SplineStripBuilder.h:77`, `library/water.frag`), lattice mask channel
(`LatticeModifierComponent.h:19`). Material features become `#define`s and compile out when off
(`engine/core/shader/ShaderManifest.h`); Lit lobes use the same pattern
(`engine/core/texture/MaterialPbr.h`).

**Scene view.** `ViewDrawMode` is Shaded, Wireframe, Shaded Wireframe, LOD Level, Overdraw
(`engine/core/render/ViewDrawMode.h:14-21`); LOD Level and Overdraw tint a material copy (RS:10491-10524).
**No mode shows vertex colors**, and tinting cannot: Lit lights and textures the color.

**Editor tooling.** `SceneTool`/`SceneTools` (`editor/scenetool/SceneTool.h:30-73`) give a tool
press/drag/release/hover/key/cancel, a 2D overlay and a status pill; `SceneToolEvent` has no pen
pressure or wheel. The Voxel brush (`editor/voxel/VoxelBrushTool.h`, `VoxelBrush.h`: settings with
presets, 3D arc-length stamper, Alt pick vs orbit gesture, decal fade, `scriptedStroke`) is the closest
template. `MeshRaycast::raycastEntity` (`engine/core/picking/MeshRaycast.h:42-67,100`) returns submesh,
triangle, barycentrics, point and normals, posed skins included; `MeshBvh` answers rays only (no
radius query). Terrain undo stores 64×64 tile XOR deltas, zstd-packed (`TerrainMapDeltaCmd.h`,
`terrain/TerrainBytes.h`); `InteractiveEdit` makes one drag one step (`command/CommandHistory.h:66-92`).
Widgets: `ui::colorField`, `ColorPickerWindow` (its eyedropper reads screen pixels), `SwatchLibrary`,
`paletteSwatchStrip`, `ui::curveField`. `LatticeBakeGltf` + `LatticeBakeCmd` write a new GLB with a
replaced attribute and swap the Model's file in one undo step. **There is no 3D mesh element
selection (vertex/face) anywhere in the editor.**

**Agents and Lua.** Precedents: `edit_terrain` (declarative ops, all-or-nothing, `dry_run`, `hash`,
jobs; `editor/mcp/tools/TerrainTools.cpp`), `edit_voxels`, `edit_sprite` (S47 echo caps). Lua Mesh
(`engine/core/script/binding/GameObjectClassesLua.cpp:2113-2230`) has a read-only `vertexCount` and no
vertex access. The `meshes` MCP group has 5 tools. No tool reads or writes per-vertex data.

## 5. Requirements

### Functional — data model and storage

- **R1** Vertex colors of a placed object live in a `VertexColorsComponent` on the entity that holds
  the `ModelComponent` or the `MeshComponent`. It references one `.vcolors` asset (`AssetRef`, new
  `AssetType::VertexColors`, GUID in `.meta`, S04). The source model or primitive is never written.
  Paintable: Models (glTF/FBX/OBJ) and built-in primitive shapes. Meshes that another system
  regenerates (spline strips and extrusions, voxel chunks, sprites, tilemaps, foliage, text, UI,
  Mesh Polygon) are refused with a message naming the generator; their colors stay theirs.
- **R2** A `.vcolors` file holds one **target** per painted mesh primitive, addressed by
  `(glTF node index, primitive index)` for models and by `submesh index` for plain meshes (with
  Merge Static Meshes on, by merged submesh). Targets not in the file keep the mesh's own colors.
- **R3** Each target stores a **base value per vertex** and a sparse list of **corner overrides**
  `(triangle corner index → value)` for corners whose value differs from their vertex. A vertex with
  no differing corner costs no override.
- **R4** **Logical vertices.** Operations work on logical vertices: GPU vertices of one target that
  share a position (within 1e-6 of the target's bounds diagonal) form one logical vertex, so UV and
  normal seams never show as color seams unless a corner override makes one. Setting a logical
  vertex sets every corner of every GPU vertex in it and removes their overrides.
- **R5** Storage format per component: **RGBA8** (default, linear, as glTF COLOR_0) or **RGBA16F**
  ("High Precision", for HDR and data channels). Changing it converts the file (undoable).
- **R6** Initial value when a target is first painted: **Asset colors** (the mesh's COLOR_0, or white
  when it has none; default), **White**, **Black** or a chosen value. Never transparent black by
  accident.
- **R7** Channel names: each component carries optional names for R, G, B, A ("Moss", "Wetness").
  When the material's Vertex Color section maps a channel (R70), its name defaults from that.
- **R8** Every write of a `.vcolors` file goes through `engine/core/io/AtomicFile.h`, debounced like
  terrain maps (`editor/util/TerrainMapFileWriter`) and flushed at scene save.
- **R9** Targets key on the **source vertex and triangle order** of the primitive. Painted
  primitives are passed to every cook (all families) the way blended primitives are
  (`ModelCookRequest::blended`, `editor/model/ModelCooker.h:40-42`): a new `painted` set keeps their
  vertex and triangle order and turns Weld Vertices off for them, so source, the editor's desktop
  cook and every export family share one order (D11). Each target records a **fingerprint**: vertex
  count, index count and a hash of the index buffer (topology; identical across families), plus a
  coarse position hash (1e-4 of the bounds) checked in the editor only. The editor-only part of the file also keeps quantized
  positions and normals per logical vertex for transfer (R60).
- **R10** **Stale data.** On load, a target whose fingerprint no longer matches (a reimport that
  changed the source topology) is transferred by nearest point with a normal filter (R60) in the editor, the
  scene is marked dirty, and an issue `vertex_colors_remapped` names the entity, target and the mean
  transfer distance. Until saved, the old file is untouched. A target with no usable match is
  reported `vertex_colors_unmatched` and drawn with its initial value.

### Functional — render path

- **R11** A target with no corner overrides binds **one extra color buffer** (`ExternalBuffer`, the
  component's format) as `submesh.attributes[COLOR]`; positions, normals, UVs, skin and index buffers
  stay the shared ones. `hasVertexColor4` is set and the Vc4 variant is used.
- **R12** A target with corner overrides gets **split vertices**: a private vertex buffer (the original
  vertices plus one copy per distinct (vertex, value) pair needed) and a private index buffer, for
  LOD0 and every baked LOD level (S54 levels index the same vertices; their indices go through the
  same remap). Morph targets and skin attributes are duplicated with their vertex. The split is built
  on a job at load and after edits; the Inspector and MCP report `split_vertices` per target.
  **LOD rule:** a corner of a LOD1+ triangle using vertex v takes the value of v's corner in the LOD0
  triangle that contains v and whose face normal is closest to the LOD triangle's (ties: lowest LOD0
  triangle id); no such LOD0 triangle → v's base value. Depth, shadow and SSAO passes keep drawing
  the shared, unsplit buffers (positions are identical), except variants that read color (lattice
  mask channel), which use the split buffers.
- **R13** Identical `.vcolors` content on copies of the same mesh shares GPU buffers through
  `MeshBufferPool`, so two identically painted copies still GPU-instance (S55).
- **R14** In the editor the color buffer of a target being edited is DYNAMIC and uploaded at most once
  per frame per buffer, all edits of the frame coalesced. In games it is IMMUTABLE unless runtime paint
  (R80) touches it.
- **R15** Disabling the component (checkbox) unbinds its buffers and the mesh draws as without it, with
  no cost left behind.
- **R16** The shader-list collector (S64) sees the Vc4 variant of every painted submesh, so an export
  does not compile it at runtime.

### Functional — the operation engine

- **R20** All writes go through `vertexcolor::applyOps(targetData, ops, options) → OpsResult`, a pure
  function of mesh geometry, current colors and the op list (no editor, no GPU). The brush, the
  selection tools, the bakers, MCP and Lua all call it.
- **R21** An op is `{op, target, filter, channels, blend, strength, …}`. **channels** is any subset of
  `rgba` (default `rgb` for colors given as RGB, `rgba` for RGBA); unlisted channels are never
  written. **blend** is one of `replace` (default), `add`, `subtract`, `multiply`, `screen`,
  `overlay`, `min`, `max`, `lerp`; **strength** 0–1 scales the change. All math is in linear space;
  colors given as hex or sRGB are converted at the boundary.
- **R22** Ops (Table 1): `set`, `fill`, `stroke`, `gradient`, `smooth`, `sharpen`, `noise`, `adjust`,
  `channel`, `replace_color`, `from_texture`, `bake_ao`, `bake_curvature`, `bake_thickness`,
  `by_direction`, `transfer`, `clear`.
- **R23** **Targets** (where an op acts): `all`; `vertices` (logical vertex ids), `faces` (triangle
  ids), `corners` (triangle×3+k), `selection` (the editor's element selection, R50); world or local
  shapes `sphere`, `box`, `capsule`, `stroke` (points with radius, optional pressure); `color`
  (match a value with tolerance, HSV ignore flags and coverage fraction); `submesh`/`material`.
- **R24** **Element** of a shape target: `vertex` (default: logical vertices inside; smooth result) or
  `face` (faces whose three corners are inside, written as corner values; hard edges). A `faces` or
  `corners` target always writes corners.
- **R25** **Filters** narrow any target: `facing` (normal within an angle of a direction), `slope`
  (angle range from up), `height` (world Y range), `curvature` (convex/concave range), `channel`
  (value range of a channel), `occluded` (skip vertices hidden from a viewpoint; brush only). Each
  filter has `invert`.
- **R26** Ops are atomic per call: one failing op rolls the batch back and names `ops[i].field` and the
  fix. `dry_run` returns the same result and writes nothing.
- **R27** Ops are deterministic: same inputs, same bytes, on every target platform. Random ops take a
  `seed` (default 0). Noise uses `engine/core/noise` (T2) so it matches its golden hashes.
- **R28** `OpsResult` reports per op `changed_vertices`, `changed_corners`, `split_added`,
  `filtered_out`, and for the batch per-channel min/mean/max before and after and a content hash.

### Functional — brush and strokes

- **R30** A `stroke` is a list of world points (pressure optional) swept as capsules between points,
  so fast strokes leave no gaps; stamps are spaced by `spacing × radius` (default 0.25) with the
  terrain/voxel arc-length stamper.
- **R31** **Strength cap per stroke** (default): a vertex never moves past `strength` of the way to the
  target value in one stroke however often it is crossed. **Build-up** (option) accumulates per stamp.
- **R32** Falloff: a curve (`ui::curveField`, presets Smooth, Linear, Constant, Sphere) plus
  **Hardness** 0–1 (inner radius with full strength). Radius in world units, measured in world space
  on scaled objects.
- **R33** Optional brush **stencil**: a grayscale texture sampled triplanar in world space with
  rotation and scale, multiplying the falloff.
- **R34** Brush modes: **Paint**, **Erase** (toward the target's initial value), **Smooth**
  (toward the neighbour average along mesh edges and across logical-vertex seams), **Sharpen**.
- **R35** Pen pressure maps to strength and/or size (toggles). `SceneToolEvent` gains `pressure`
  and `wheel`.

### Functional — generators and bakes

- **R41** `from_texture`: for each corner, the texture is averaged over the corner's area (the part of
  its triangle nearer to it than to the other corners), with ≥ 16 stratified bilinear samples in UV
  space, decoded to linear when the texture is color data (sRGB import). Sources: a texture asset, or
  a material slot of the mesh (`albedo`, default: albedo map × base color factor; also `emissive`,
  `occlusion`, any named texture). UV set selectable. Option **Keep texture seams**: where a logical
  vertex's corners differ by more than ΔE 2 (OKLab), write corner overrides (hard edge), else the
  vertex average. The result reports `mean_delta_e` and `p95_delta_e` between texture and result, and
  `under_sampled_faces` (faces covering more than 64 texels per vertex), so the loss is measurable.
- **R42** `bake_ao`: per vertex, cosine-weighted hemisphere rays (default 64, seeded) against the
  object alone or the whole scene's static meshes (`MeshBvh`), max distance, written as
  `1 - occlusion` into the chosen channels. `bake_thickness`: the same along `-normal`.
- **R43** `bake_curvature`: signed convexity from neighbour normals and positions, remapped to 0–1
  (0.5 flat), with a blur radius in edges.
- **R44** `by_direction`: value from the normal against a direction (top-down moss, bottom dirt), with
  a smoothstep range; `gradient` with `type: height` covers height-based fills.
- **R45** `gradient`: `linear` or `radial` between two points (world or local), or `height`/`axis`
  over the target's bounds; color **stops** (≥ 2) each with value and strength; interpolation
  `linear`, `oklab` (default for colors, OKLab maths from `engine/core/pixelart/Palette.h`), `hsv`
  with hue `near/far/cw/ccw`; `extend` off/forward/backward/both; element `vertex` or `face`.
- **R46** `noise`: value, simplex or cellular with scale, octaves, seed, world or local space.
- **R47** `adjust`: levels (in/out black/white, gamma), brightness/contrast, HSV shift, invert, clamp.
- **R48** `channel`: copy, swap or invert channels, or **pack** a channel from another channel or a
  constant (VertXArtist's packer), so masks can be moved between channels.
- **R49** `replace_color`: every vertex/corner matching a value (tolerance) gets a new value; with the
  "Colors on this mesh" list (R54) it is the low-poly recolor.

### Functional — selection (exact coloring)

- **R50** The editor holds an **element selection** per target: a mode (**Vertex**, **Face**,
  **Corner**) and a set of ids. It is editor state, part of selection undo (S24), cleared when the
  tool exits unless pinned. MCP and Lua target it as `selection`.
- **R51** Selection tools: click; drag box; lasso (tool option); Shift adds, Ctrl removes; **X-Ray**
  toggle selects through to hidden elements (default off: only visible elements, by depth test).
- **R52** Selection commands: All, None, Invert, Grow, Shrink, Linked (connected faces across seams),
  Similar Color (tolerance, HSV ignore flags, coverage), By Normal (angle), Flat Region (adjacent faces
  within an angle: selects a whole "face" of a low-poly model in one click), By Channel Range.
- **R53** **Apply panel**: a color (`ui::colorField`, hex, numeric RGBA 0–1 or 0–255) with channels,
  blend and strength, and **Apply** (Enter). In Face and Corner mode the result has hard edges (R3);
  in Vertex mode it is shared. Also: **Gradient across selection** (axis or two picked points) and
  **Copy color from selection** (average, to the color field and clipboard).
- **R54** **Colors on this mesh**: the distinct values of the selected target(s) (rounded to 8 bits,
  sorted by hue, counts), each with Select and an editable swatch that recolors every match
  (`replace_color`, undoable).
- **R55** **Palettes**: the S43 `.palette` assets and S27 swatch libraries through
  `paletteSwatchStrip`; click sets the color, Shift-click applies it to the selection.

### Functional — transfer, export and texture bake

- **R60** `transfer`: from another entity's colors (or a target's own pre-reimport snapshot), nearest
  point in world or local space through a uniform grid, with max distance and a normal filter
  (default 60°); unmatched elements keep their value or take the nearest overall (option).
- **R61** **Export as Model…**: writes a new self-contained `.glb` with COLOR_0 (format of the
  component) for every target, hard edges split in the file, through the `LatticeBakeGltf` path;
  option **Replace in scene** swaps the Model's file and removes the component in one undo step
  (`LatticeBakeCmd` pattern).
- **R62** **Bake to Texture…**: rasterizes the target's colors into a new PNG in UV space (chosen UV
  set, size, padding by dilation, sRGB or linear), written atomically and imported.

### Functional — materials (every use of the colors)

- **R70** Built-in Lit gets a **Vertex Color** section with **Use**:
  - **Tint** (default; today's behaviour, so old projects render unchanged): RGB multiplies albedo,
    A multiplies alpha (toggle "Alpha multiplies opacity", default on, as today).
  - **Masks**: each of R, G, B, A maps to one of None, Occlusion, Roughness (multiply or replace),
    Metallic, Emission (mask of the emissive color), Opacity or Albedo Tint (grayscale); plus "RGB
    tints albedo" when R, G and B are all unmapped. Texture-layer blending is `library:vertex_blend`
    (R71); Lit gains no detail layer.
  - **Off**: vertex colors are ignored by the shader (the stream is still there for other systems).
  Each enabled mapping is a `#define` (MaterialPbr pattern); a material without vertex colors, or in
  Tint mode, costs what it costs today.
- **R71** `library:vertex_blend`: a lit library shader blending a base layer and up to four layers
  weighted by R, G, B, A. Per layer: albedo (height in alpha), normal, optional ORM, tiling, and
  a height-blend contrast. Weights: `w_base = max(0, 1 - (r+g+b+a))`, layers by their channel, then
  height-adjusted `w_i' = max(0, h_i + w_i - (max_j(h_j + w_j) - contrast))` and renormalized (no
  `step`). Layer count is a `@keywords` choice (2–5) so unused layers compile out. Optional triplanar
  per layer (`@feature TRIPLANAR`). It fits 16 fragment samplers at 5 layers with ORM off (GLES3).
- **R72** Data channels: the painter's channel names show what each channel feeds when known: Lit
  mappings, `vertex_blend` layers, foliage wind (`windMask = VertexColor`), lattice mask channel. Custom shaders read the raw stream through `@require rawcolor`; `docs` explains it.
- **R73** The Vertex Paint window warns when the selected entity's material ignores the channels
  being painted (Off, or Tint while painting A only, …) with a one-click fix.

### Functional — runtime paint (gameplay)

- **R80** Lua `VertexColors:paint(worldPos, opts)` paints at runtime with `radius`, `value`,
  `channels`, `strength`, `falloff`, and optional `hold` and `fade` seconds (game time). Runtime paint
  is a **separate transient layer** combined over the authored colors at upload; it never changes the
  `.vcolors` asset.
- **R81** Per vertex the transient layer keeps a fixed-size state (current value, per-channel touched
  mask, hold end, fade rate): memory is bounded whatever the number of calls.
- **R82** Fades are recomputed at most 10 times per second and uploaded only when bytes change; a mesh
  with no live paint costs nothing per frame. `clearRuntime()` drops the layer.
- **R83** Runtime paint needs CPU geometry: it uses `ModelCpuData::ensure`, which re-reads released
  bytes from the model file; the first `paint` on a target that had to re-read logs its cost once
  with the fix "enable Read/Write in the Model Importer" to keep the bytes resident.

### Platform and backends

- **R90** Only per-vertex attributes and fragment math: no compute, SSBO or texture fetch in the vertex
  stage. UBYTE4N and HALF4 vertex formats on GL 4.1, GLES3/WebGL2, Metal, D3D11, Vulkan.
- **R91** All ops, bakes and runtime paint run on every export target (CPU); the editor-only parts are
  the tools, dialogs, the transfer snapshot and texture bake.
- **R92** Exports strip the editor-only part of `.vcolors` files and refuse a target whose topology
  fingerprint does not match the family's cooked primitive (R10 not yet run) with a message naming
  the entity and the fix (open and save the scene). Lossy position quantization of a family does not
  make a target stale.

### Performance

- **R95** A scene with no `VertexColorsComponent` does no extra work. A painted target costs 4 bytes
  per vertex (RGBA8) or 8 (RGBA16F) of GPU memory, plus a full private copy of its vertex and index
  data when it has corner overrides.
- **R96** Editor brush: one stamp on a 100k-vertex target ≤ 2 ms CPU (desktop reference machine,
  `perfSlack()`), using a per-target uniform grid of logical vertices built on a job when the tool
  arms (≤ 150 ms for 1M vertices).
- **R97** Ops over more than 250k elements, and every bake, run as a job with progress and Cancel in
  the editor, and as an MCP job (`wait`, `timeout_seconds`).
- **R98** `from_texture` with 16 samples per corner on 100k vertices ≤ 1.5 s; `bake_ao` with 64 rays
  on 100k vertices ≤ 5 s (desktop, jobs).
- **R99** Runtime `paint` on a 10k-vertex mesh ≤ 0.3 ms CPU on the mobile reference device per call,
  one upload per buffer per frame.

## 6. Design constraints & decisions

- **D1** Per-object sidecar + explicit export (chosen by the owner). Inline YAML and editing the model
  are rejected (scene bloat; shared-asset leaks seen in two reference tools).
- **D2** Per-corner values with splitting only where corners disagree (chosen by the owner, option B).
  The common case (no overrides) keeps shared geometry and costs 4 bytes per vertex.
- **D3** One operation engine (`engine/core/vertexcolor/VertexColorOps.h`) in the T1 mold; the editor
  only gathers input and draws. The brush is a stream of `stroke` ops; Apply is a `set`/`fill`;
  generators are ops.
- **D4** Values are linear and blending happens in linear space; the UI shows sRGB swatches and hex,
  converting at the boundary. RGBA16F exists for data that needs it.
- **D5** Logical vertices hide seams; corners create intended hard edges. The two concepts are the
  whole mental model shown to users: "Vertex = smooth, Face/Corner = sharp".
- **D6** The vertex spatial index is a per-target uniform grid in the vertexcolor module (not a new
  `MeshBvh` query); occlusion uses `MeshRaycast`.
- **D7** Undo stores per-target XOR deltas of base values in 4,096-vertex chunks, zstd-packed with
  `packTerrainBytes`, plus before/after override tables (packed); refused if the target's
  fingerprint changed.
- **D8** The Vertex Color draw mode is an editor-only substitution with an unlit debug shader reading
  the raw stream and a channel uniform (`library:vertex_color` extended), loaded only while the mode
  is on.
- **D9** Material work extends built-in Lit (Tint/Masks/Off) and adds one library shader; no shader
  graph.
- **D11** One vertex order everywhere: painted primitives keep source vertex and triangle order in
  every cook (R9). Cost: painted primitives lose the cook's vertex-cache/fetch reordering and welding
  (measured in the M1 benchmark, reported in the Build Report).
- **D12** Ops run in the **bind pose** in the object's current transform, so they are deterministic.
  The editor brush and Lua `paint` with a raycast hit map the posed hit to bind pose through its
  triangle and barycentrics, so a stroke lands under the cursor on a posed character; a plain world
  point given to MCP or Lua is read in bind pose (documented).
- **D10** Tool names follow `verb_noun` (`tools/mcp/tests/test_tool_conventions.py`) with the area noun
  first in the noun: `edit_mesh_colors`, `sample_mesh_colors`, `bake_mesh_colors`. Op items are
  `anyObject` with an `op` enum; the handler validates fields (S47 D4) to stay under 1,500 characters.

### API sketch: engine

```cpp
namespace jasperengine::vertexcolor {
    enum class Format : uint8_t { RGBA8, RGBA16F };
    struct TargetKey { int32_t node = -1; int32_t primitive = -1; int32_t submesh = -1; };
    struct TargetData {               // one painted primitive
        TargetKey key; Fingerprint fingerprint;
        std::vector<Vector4> base;    // per GPU vertex, linear (stored as Format)
        std::vector<std::pair<uint32_t, Vector4>> corners;   // sorted by corner index
    };
    struct MeshView;                  // positions, normals, uvs, indices, logical vertex map, grid
    OpsResult applyOps(TargetData&, const MeshView&, std::span<const Op>, const ApplyOptions&);
    SplitResult buildSplit(const TargetData&, const MeshView&);   // R12, jobs-safe
}
```

## 9. Risks & defaults

- **8-bit linear banding** in dark visible colors (glTF's own convention). Default RGBA8 linear;
  RGBA16F is the escape. Revisit with sRGB-encoded RGBA8 only if artists report banding.
- **Source edits**: a reimport that changes the source topology still makes targets stale; R10
  transfer handles it. Cook settings no longer do (D11).
- **Dynamic batching** takes float4 colors only (`RenderSystemBatch.cpp:111-118`): painted meshes of
  ≤ 64 vertices leave dynamic batching. Accepted; extending the batcher is a follow-up.
- **Split memory** on big smooth meshes with many hard edges can double their vertex data per object;
  the Inspector shows the count; Export as Model is the shared alternative.
- **Texture units** for `vertex_blend` on GLES3: 5 layers × (albedo+normal) + shadows/IBL is near 16;
  default ORM off at 5 layers, enforced by the manifest.
- **More than four channels**: out of scope (one stream). A later spec can add `COLOR_1`.
- **Merge Static Meshes toggled after painting** changes target keys; the transfer path remaps, with
  a warning.

## Deviations

- **D8, the view's channel** (render stream): the Draw Mode's unlit debug shader is a view variant of
  each submesh's own shader (MESH bits `Vcv`, `Vcs`, `Vk1`, `Vk2`, `includes/vertex_color_view.glsl`)
  rather than `library:vertex_color` with a channel uniform, and the channel is a variant bit. A
  substituted library shader would need the submesh loaded again on another vertex layout and
  bindings, which a per-view draw mode cannot do (the Game view of the same scene keeps drawing
  shaded); the view variant keeps its base's bindings, so it draws through the same pipeline
  description, skinned, morphed, instanced, VAT and lattice meshes included. A uniform would add a
  block to every view variant. Cost: the first switch to a channel compiles its variants (the mesh
  draws shaded meanwhile). A library shader that reads no vertex colour (no `@require color` or
  `rawcolor`) shows white in the view, and an OIT submesh draws shaded.
- **R9, R10, the snapshot** (fixups): the editor-only section keeps positions and normals per GPU
  vertex, not per logical vertex (the transfer matches GPU vertices, so seams keep their own
  values), and, for a target with corner overrides, the triangle list it was painted on. With it the
  remap and `transfer` carry hard edges: each new corner takes the old corner at its vertex's place
  whose triangle is nearest a point inside its own triangle (the side of the edge it lies on), so
  overrides are written only where corners differ. This changed the file layout: `VCOLORS_VERSION`
  is 2, version 1 files (no triangles; they transfer per vertex) still read and are written back as
  version 2 (`engine/tests/core/fixtures/vertexcolor/version1.vcolors`).
- **R60, transfer from another GameObject** (fixups): `editor::vertexcolor::transferSource` builds
  the source (every target's values in world space and, when one has hard edges, every corner's)
  for the Vertex Paint window's Transfer From and `edit_mesh_colors`' `transfer`.
- **R61, Export as Model** (fixups): the file is written by editing the model's glTF JSON
  (`GltfDocument`), not through `LatticeBakeGltf`. Merge Static Meshes models write each merged
  submesh back into the file primitive it was made of (the loader's order: mesh nodes ascending,
  primitives in order, reversed), refused when that primitive's triangles are not the painted ones.
  A plain mesh (a built-in primitive) and an OBJ Model are written from their CPU geometry: one node,
  one primitive per submesh, a glTF metallic-roughness material per submesh (factors, the five
  texture maps by URI, alpha mode, double sided); a linked `.material`, a library shader or the Lit
  extensions are not carried and are set on the Model again. Replace in Scene on a plain mesh removes
  its Mesh (an undo puts the geometry back), adds a Model of the new file, and removes the component,
  one undo step.
- **R71, the base weight** (render stream): with fewer than five layers, `w_base` is
  `1 - (r + g + ...)` over the channels of the layers there are (at five, `1 - (r+g+b+a)`); the
  height-blend contrast is per layer (the formula with one contrast is the case of equal ones); ORM
  maps reach up to four layers (at five the factors apply), which keeps five layers within 16
  fragment textures on GLES3 with the lights.
- **AC6, the test file** (MCP stream): the MCP tests extend `tools/mcp/tests/test_meshes.py`, the
  meshes group's CI file on a new empty project, instead of adding `test_mesh_colors.py`: AGENTS.md
  asks to extend an existing file, since every MCP file costs shard time. Their names start
  `test_mesh_colors_` or `test_bake_mesh_colors_`, so `-k mesh_colors` selects them; the group's
  hidden-until-enabled check is that file's `test_meshes_group_is_hidden_until_enabled`.
- **R120-R124, result shapes** (MCP stream): `edit_mesh_colors` reports `changed`, `ops[]`, `stats`
  (min/mean/max; `sample_mesh_colors` gives percentiles and histograms) and `hash` per target in
  `targets[]`, the sum in `changed`; `get_model_info` and `get_entity` list `vertex_colors`, one
  entry per target with its mesh GameObject (`mesh`) and submesh (`mesh_submesh`).
