# S29 — Version control integration (Git + LFS locks, SVN, overlays, commit, semantic scene diff)

Wave 3. Report: `docs/openengine-analysis/08-editor-infrastructure.md` §1 "Version control", §5 items 7–8.

## 1. Goal

Users and agents can see, review and record their changes without leaving the editor. Every
asset row and scene shows its VCS state. Binary assets can be locked, so two artists never edit
the same `.fbx`. Commits and logs work from an ImGui dialog, and reverts are undoable. A semantic
diff of a scene or prefab against HEAD works at the entity, component and property level, with
per-property "Revert to Baseline", so a scene change can be reviewed like code. A scene-aware
three-way merge removes most conflicts that come from teams editing one scene. Git (with Git LFS
locking) is the main target. SVN is the second provider, behind the same interface.

## 2. Scope

**In scope**
- A provider-neutral `IVcsProvider` covering status, diff/base content, stage/unstage,
  commit, log, revert, lock/unlock, and branch plus ahead/behind. Git also gets fetch, pull
  (fast-forward only) and push.
- `VcsStatusPoller` (one background thread, wake with cooldown) and `ProcessExec`, an
  argv-only process runner that never goes through a shell.
- Providers: **Git CLI** (with `git lfs` locking) and **SVN CLI**.
- Editor UX:
  - status overlays in the Project window and the Hierarchy;
  - a lock banner in the Inspector;
  - a Commit window, a History (log) window and a Scene Diff window;
  - an undoable file revert;
  - lock-on-edit for lockable files;
  - a Conflicts window with "Smart Merge".
- A semantic scene/prefab diff (`SceneYamlModel` + `SceneDiff`), per-property, per-component and
  per-entity "Revert to Baseline" (undoable through S24).
- A scene three-way merge (`SceneMerge`) used by a git merge driver
  (`jasperengine-editor merge-scene`) and by the Conflicts window.
- Merge-friendly YAML: derived transform data is no longer written, and diff/merge ignore it.
- `.gitignore`/`.gitattributes` generation extended with LFS, lockable and merge-driver lines.
- MCP tools and a status resource. Tests in temporary git/svn repos inside the docker images.

**Out of scope**
- libgit2 and any in-process VCS library (decision D1).
- Their Diversion and Lore providers, and Perforce (report §6: niche; Perforce has no test server we can ship).
- Entity-level locks (their `HierarchyVcsController` entity lock UI): a lock is per file.
- Branch create/switch, rebase, stash, interactive conflict editing of non-scene text, and
  credential management. The user's git/svn credential helpers and SSH agent are used as they are.
- Their retained-mode HTML/CSS VCS UI (`Source/VersionControl/Ui/*`). It is rebuilt in ImGui,
  per the do-not-copy rule on their editor UI toolkit.
- Runtime/Lua API. This is editor-only functionality and never ships in a game.

## 3. Current state

- **No VCS integration.** The editor only writes `.gitignore` and `.gitattributes`
  (`editor/Project.cpp:5230-5325`, `Project::writeVersionControlMetadata`, declared at
  `editor/Project.h:1172`). A file is refreshed only while its first line carries the
  "Generated by JasperEngine Editor." marker.
  - The setting is `editor.version_control_files` (`editor/mcp/tools/ProjectTools.cpp:1318`,
    `editor/window/dialog/ProjectSettingsWindow.cpp:1648`).
  - `.gitattributes` forces LF on `*.scene`/`*.prefab`/`*.yaml`/code and marks images, models and
    audio `binary`. It has no LFS, no `lockable` and no merge driver.
  - S04's new `*.meta` sidecars are not covered.
- **Process execution is shell-only.** `editor/util/CommandRunner.{h,cpp}` (527 lines) runs a
  *command string*:
  - POSIX: `/bin/sh -c` via `posix_spawn`, with a process group for tree kill (`:374-404`);
  - Windows: `cmd.exe` + job object (`:63`, `:228-240`).
  - Paths and commit messages would need shell quoting, which is an injection risk. It also has
    no timeout, no stdin control and no separate stderr.
- **Scene format** (`editor/Stream.cpp`, e.g. `tools/fixtures/prefab-runtime/Main Scene.scene`):
  - Entities carry a stable per-file integer `entity:` id, preserved on load
    (`Stream::decodeSceneProjectEntities`, `editor/Stream.cpp:3224-3257`, reserves every
    serialized id).
  - Hierarchy is nested under `children:`. Prefabs (`*.prefab`) hold a flat `members:` list plus
    `root:` and `nextEntity:`.
  - Transforms also write **derived** data: `worldPosition/Rotation/Scale`, `localMatrix`,
    `modelMatrix`, `normalMatrix` (`editor/Stream.cpp:5161-5166`, read back at `:5187-5192`).
    Every moved parent then rewrites the derived data of its whole subtree, which is pure diff
    and merge noise.
- **Undo:** `editor/command/Command.h` has no name. Histories are per scene plus a project history
  (`Project::getProjectCommandHistory`, `editor/Project.h:1165`). S24 adds names and one
  timeline.
- **Inspector/Hierarchy hooks that already exist:**
  - prefab override gutter bar (`InspectorWindow::drawPrefabOverrideBar`,
    `editor/window/InspectorPrefabBar.cpp:149`);
  - per-row overlays (`HierarchyWindow::drawPrefabRowOverlay`,
    `editor/window/HierarchyPrefabRows.cpp:118`);
  - a read-only Inspector mode (`InspectorWindow.h:281`).
  - Icons come from `external/IconsFontAwesome6.h`.
- **MCP:** `ToolDef` carries `annotations.readOnly/destructive` and a `ToolActivity` busy policy
  (`editor/mcp/McpRegistry.h:20-50`). Long operations use `McpJobs` (`editor/mcp/McpJobs.h`).
- **Docker:** `docker/linux.Dockerfile:8` installs `git`, but not `git-lfs` or `subversion`.

## 5. Requirements

### Functional — core

- **R1** `editor/vcs/IVcsProvider.h`. Status types:
  ```
  VcsChange { path, index, worktree, conflict, lock, remoteChanged }
  index/worktree ∈ {Unmodified, Added, Modified, Deleted, Renamed, Untracked, Ignored}
  lock ∈ {Unsupported, Unlocked, LockedByMe, LockedByOther}, plus lockOwner
  ```
  Operations, all taking path *lists*:
  - `status()`, `baseContent(path, rev = "HEAD")`, `textDiff(path)`
  - `stage(paths)`, `unstage(paths)`, `commit(paths, message)`, `log(path?, limit)`, `revert(paths)`
  - `lock(paths)`, `unlock(paths, force)`, `isLockable(path)`
  - `branchInfo()` → `{name, headOid, ahead, behind, upstream}`
  - optional `fetch()`, `pull()`, `push()`, advertised through `capabilities()`

  Every call returns `VcsResult{ok, exitCode, message}`. None of them throws.
- **R2** `editor/vcs/ProcessExec.{h,cpp}`:
  `run({exe, args, cwd, env, stdinData, timeoutMs, maxOutputBytes, cancelToken}) → {exitCode, stdout, stderr, timedOut, truncated}`.
  - No shell on any platform. Each `args[i]` reaches the child as exactly one argv entry.
  - POSIX:
    - `posix_spawn` of an **absolute** path;
    - argv/envp built before the spawn;
    - new session (`POSIX_SPAWN_SETSID`; `SETPGROUP` fallback);
    - stdin from `stdinData` or `/dev/null`;
    - both pipes drained with `poll()`, all fds `O_CLOEXEC`;
    - on timeout or cancel, SIGTERM to the group, then SIGKILL after 2 s.
  - Windows:
    - `CreateProcessW` with an absolute `lpApplicationName`, their `QuoteArgument` rules,
      `CREATE_NO_WINDOW`, and a kill-on-close job object;
    - stdin through a pipe or `NUL`.
  - `CommandRunner` (shell, for builds) stays as it is, and VCS code never uses it.
- **R3** Executable resolution:
  - the per-user setting first, else `PATH`;
  - relative `PATH` entries and the project directory are skipped, so a planted `git.exe` in the
    project never runs;
  - macOS also probes `/opt/homebrew/bin`, `/usr/local/bin` and `/usr/bin`. It uses `/usr/bin/git`
    only when `xcode-select -p` succeeds, so the CLT install dialog never pops up.
  - Minimum versions, checked once: Git 2.30, git-lfs 3.0, svn 1.10. Below that, the provider is
    unavailable with a message.
- **R4** Every git call:
  - Pass `-c core.fsmonitor=false -c core.pager=cat -c color.ui=false --no-optional-locks`.
    `diff`/`show` also get `--no-ext-diff --no-textconv`.
  - Set `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never` and `LC_ALL=C`.
  - Put `--` before pathspecs. Pass more than 64 paths through `--pathspec-from-file` with
    `--pathspec-file-nul` and a temp file in `.jasperengine/vcs/`.
  - Commit messages go through `-F -` (stdin).

  Every svn call passes `--non-interactive --xml` (where supported) and `--encoding UTF-8`;
  messages go through `-F <tempfile>`, path lists through `--targets <tempfile>`.

  Timeouts: local ops 30 s, commit 120 s (hooks run), network ops 300 s. All are cancellable.
- **R5** `editor/vcs/VcsStatusPoller` (port). Defaults:
  - status interval 10 s (setting range 2–120);
  - wake cooldown 500 ms;
  - wake on editor focus-in, after every editor save (S03 publish listener), and on S05
    `FileWatcher` batches outside `.jasperengine/`, `.git/` and `.svn/`.

  The lock/remote refresh runs on a separate slow cadence:
  - LFS `locks --verify --json` and `svn status -u --xml`: 60 s by default, range 30–600, `0` turns it off;
  - also right after any lock/unlock/commit/push.

  The ignored set (`status --ignored=matching`) refreshes at startup and when a `.gitignore` changes.
- **R6** Snapshot. The poll builds a sorted flat vector keyed by repo-relative path, with lexical
  keys (`VCSPathKey`), and publishes it as `std::shared_ptr<const VcsSnapshot>`. The main thread
  swaps it in once per frame and bumps `snapshotVersion`. Readers never block on the poller.
  Directory rows aggregate their children: the worst state wins, in the order
  Conflict > LockedByOther > Modified/Added/Deleted > Untracked > Clean.
- **R7** Detection:
  - Walk up from the project root for `.git` (a dir, or a file for worktrees and submodules)
    or `.svn`; the nearest one wins.
  - Confirm with `git rev-parse --show-toplevel` or `svn info --xml`.
  - A project in a repository subdirectory works. Status is limited to the project directory
    pathspec.
  - Project setting `editor.vcs.provider: auto|git|svn|none` (project.yaml, default `auto`).
- **R8** S04 `.meta` pairing. `x.png` and `x.png.meta` act as one item for stage, commit, revert
  and the commit-list row; the meta inherits the asset's checkbox. Lock applies to the asset file
  only. A lone `.meta` change shows as its own row.
- **R9** Git specifics:
  - status is `git status --porcelain=v2 -z --branch --untracked-files=all -- <projectDir>`;
    `# branch.oid/head/upstream/ab` fill `branchInfo` at no extra cost;
  - `stage` = `add -A --`, `unstage` = `restore --staged --`;
  - `commit` = `commit --only -F - -- <paths>` after staging untracked selections. Other staged
    files the user had are left staged, and hooks run (never `--no-verify`);
  - `log` = `log -z --format=%H%x1f%an%x1f%aI%x1f%s -n <limit> [-- path]`;
  - `baseContent` = `cat-file blob <rev>:<relpath>`;
  - `revert` = `restore --source=HEAD --staged --worktree --`;
  - `pull` = `pull --ff-only` only;
  - `push` = `push` with no flags. Force is never offered.
  - `isLockable` = `check-attr -z --stdin lockable`, cached per snapshot;
  - locks via `lfs lock --json` / `lfs unlock --json [--force]`.
- **R10** SVN specifics:
  - status `status --xml` (local) plus `status -u --xml` (slow cadence: lock owner and
    out-of-date flag);
  - `commit -F msg --targets list`;
  - `revert --targets list`;
  - `log --xml -l <n>`;
  - `cat -r BASE`;
  - `isLockable` = `svn:needs-lock` set;
  - `lock -m "<editor user>" --targets`, `unlock [--force]`.
  - fetch/push are unsupported. `pull` maps to `update`.
- **R11** Undoable revert, `RevertFilesCmd` (S24, one timeline, name "Revert N files"):
  - Copies each file and its `.meta` to `.jasperengine/vcs-backup/<cmd-id>/` before calling
    `revert`.
  - Undo restores the copies through S03 atomic writes. Redo reverts again.
  - Open scenes/prefabs whose file changed are reloaded. A dirty open scene asks first:
    "Revert discards unsaved changes in <scene>".
  - Backups are deleted when the command leaves history (S24 cap) or at project close.
  - Untracked or newly added files are not revertible; the UI offers Delete (existing
    `DeleteFileCmd`).
  - If the provider revert fails, the command reports the error and is not pushed.
- **R12** Lock-on-edit, per-user setting `editor.vcs.lock_on_edit: off|ask|auto` (default `ask`).
  Applies to lockable files that are not `LockedByMe`.
  - **Scenes/prefabs:** fires when the first command makes the document dirty (S24 history hook).
  - **Binary assets:** fires before an import-settings/meta edit or an in-editor overwrite.
  - `ask` shows "Lock <file>?" with Lock / Edit Without Lock / Cancel. `auto` locks in the
    background and shows a toast on failure.
  - `LockedByOther` always warns ("Locked by <owner>"). The edit continues only after "Edit
    Anyway".
  - A save refused by S03 R6 (`ReadOnlyTarget`, which LFS/needs-lock produce) offers
    "Lock and Save" and "Make Writable and Save".

### Functional — semantic diff and merge

- **R13** `editor/vcs/scene/SceneYamlModel` parses a `.scene` or `.prefab` YAML into
  `{documentKeys, objects: id → {name, parentId, siblingIndex, components: key → YAML::Node}}`.
  - Nested `children` are flattened; prefab `members` are taken as they are.
  - Scene-level keys (`scene:`, `mainCamera`, `sceneType`, `prefabs`, …) form a pseudo-object
    "Scene Settings".
  - The baseline is run through the S03 migration table (`StreamMigrations`, raw-YAML
    migrations) up to the current `formatVersion` before comparison.
  - It is pure: no engine and no registry, so it is usable from CLI and tests.
- **R14** `SceneDiff(base, current)`:
  - Entities: Added / Removed / Modified, Reparented, Reordered (sibling index).
  - Components: Added / Removed / Modified.
  - Properties: path, baseline value, current value (YAML flow strings).
  - Sequences of maps are keyed: `scripts` by `(type, path)`, script `properties` by `name`,
    `prefabs` by `guid`. Other sequences compare whole.
  - Scalars compare numerically with a relative epsilon of 1e-6 for floats.
  - The `kDerivedKeys` table (the transform keys from §3) is ignored.
  - Property paths look like `transform.position`,
    `script.scripts[lua:Enemy.lua].properties[speed].value`.
- **R15** The current side comes from the open document, so unsaved edits show:
  - `Stream::encodeSceneProject` for scenes, the prefab stage encoder for prefabs;
  - debounced 500 ms after the last history change, and only while a consumer is active
    (Scene Diff window open, or "Show VCS Changes" on).
  - Parse and diff run on an S06 background job. A closed document diffs the file on disk.
  - The baseline is memoized on `(path, headOid, blobOid)`.
- **R16** Revert to Baseline. Undoable commands, each one undo step, named "Revert <path> to Baseline":
  - **property:** decode the baseline component node into a temporary component and apply the
    one property through the existing property command path. Prefab instance members go through
    the prefab-override-aware path (`PrefabOverrideCmd`), so the override set stays consistent;
  - **component:** add, remove or replace it with `ComponentValuesCmd`;
  - **entity:** re-create a Removed entity from the baseline YAML, keeping its id when free and
    otherwise remapping; delete an Added entity; restore the parent and sibling index of a
    Reparented one.
  - "Copy Baseline Value" puts the YAML flow string on the clipboard.
- **R17** `SceneMerge(base, ours, theirs)`, a three-way merge at the property level over R13
  models:
  - A property changed on one side takes that side; changed on both sides with equal values,
    either; with different values, a **conflict**.
  - An entity added on both sides with the same id but different content keeps ours. Theirs is
    renumbered above `max(nextEntity, max id)`, and references are remapped in known fields
    (`EntityReference` script properties, `mainCamera`, `prefabInstance.memberIds`, prefab `root`).
  - An entity deleted on one side and modified on the other is a conflict.
  - Prefab `nextEntity` takes the max.
  - The output is encoded in the canonical key order of `Stream`, so a re-save makes no diff.
- **R18** `jasperengine-editor merge-scene <base> <ours> <theirs> <path>` (headless, before
  backend start, like `export` in `editor/main.cpp:21`). It has git merge-driver semantics:
  - it writes the result to `<ours>` and exits 0 when there are no conflicts;
  - on conflicts it writes ours plus every non-conflicting change, records them in
    `.jasperengine/merge/<path>.conflicts.yaml` (base/ours/theirs value per property), and exits 1;
  - unparseable input: exit 2, `<ours>` untouched.
- **R19** Conflicts window (Window > Version Control > Conflicts). It lists files with
  `conflict`:
  - Scenes/prefabs:
    - **Smart Merge** builds the three inputs from git index stages `:1:/:2:/:3:` or the svn
      `.rOLD/.mine/.rNEW` files and runs R17;
    - each remaining conflict is resolved with Ours/Theirs per property;
    - **Mark Resolved** writes the file and runs `git add` / `svn resolve --accept working`.
  - Other files offer Use Ours / Use Theirs / Open in External Tool.
  - Conflicted scenes refuse to open until resolved. The file still contains the driver result,
    which is loadable, but loading it would hide the conflict.

### Data & compatibility

- **R20** Stop writing derived transform keys (`editor/Stream.cpp:5161-5166`):
  - `formatVersion` +1 with an S03 migration that drops them;
  - decode still accepts them and recomputes world/derived matrices on load
    (`transform.needUpdate`);
  - the runtime never reads scene YAML (scenes reach games through generated code), so this is
    editor-only.
- **R21** `writeVersionControlMetadata` (keeps the marker rule):
  - Adds `*.meta text eol=lf` and `*.scene/*.prefab merge=jasperengine-scene`.
  - When `editor.vcs.lfs: true`: `filter=lfs diff=lfs merge=lfs -text` for every binary pattern
    already listed, plus `*.psd *.exr *.hdr *.ktx2 *.basis *.blend *.mp4 *.webm`, and `lockable`
    on the same patterns.
  - `editor.vcs.lock_scenes: true` adds `*.scene lockable` and `*.prefab lockable`.
  - Defaults: `lfs` true for projects **created** by this version (Project Hub, S27), absent →
    false for existing projects. `lock_scenes` false.
  - `.gitignore` adds `.jasperengine/` (already there) and `*.orig`.
  - Scenes, prefabs and meta files are never LFS patterns.
- **R22** "Set Up Smart Merge" (VCS settings) runs
  `git config --local merge.jasperengine-scene.driver "<abs editor> merge-scene %O %A %B %P"`
  and `merge.jasperengine-scene.name`. Without it, git uses its text merge. Status shows
  "Smart merge: not set up" when the attribute is present but the driver is not.

### Platform & backends

- **R23** Editor on Windows, Linux and macOS only. Nothing links into engine or runtime targets.
  The editor builds and runs with VCS disabled when no executable is found. Web/mobile are not
  affected.

### Performance

- **R24** No process is ever spawned on the main thread. In debug builds `ProcessExec::run`
  asserts that it is not on the main thread.
- **R25** Main-thread budgets:
  - snapshot swap + directory aggregation ≤ 1 ms for 20k entries;
  - per-row status lookup ≤ 2 µs (binary search);
  - Hierarchy/Project overlays ≤ 0.3 ms per frame at 500 visible rows.
- **R26** Background budgets:
  - status poll on a 10k-file repo ≤ 400 ms on the CI runner, and zero spawns while idle between
    intervals;
  - scene diff of a 2,000-entity scene ≤ 150 ms (parse both sides + diff) on a job thread;
  - main-thread encode of the current side ≤ 10 ms for 2,000 entities. Over that, the overlay
    falls back to the on-disk diff and says "Showing saved changes".

### Agent UX (MCP, CLI)

- **R33** MCP tools in `editor/mcp/tools/VcsTools.cpp`. Every path is validated to lie inside the
  project root and contain no NUL. A revision must match `^[0-9a-fA-F]{7,64}$|^HEAD(~[0-9]{1,4})?$`
  (git) or `^([0-9]+|BASE|HEAD)$` (svn). No parameter is ever turned into a flag.

  |---|---|---|---|

  | `vcs_diff` | readOnly | `path`, `rev="HEAD"`, `max_bytes=65536` | unified text diff |
  | `vcs_log` | readOnly | `path?`, `limit=50 (≤200)` | |
  | `scene_diff` | readOnly | `scene` (path or open id), `rev="HEAD"`, `source="editor"\|"disk"`, `changed_only=true` | R14 structure |
  | `scene_diff_revert` | Edit, undoable | `scene`, `entity`, `component?`, `property?` | R16; returns the undo name |

  "Version control" section saying that agents run `scene_diff` before `vcs_commit`, and that

- **R34** CLI: `jasperengine-editor merge-scene` (R18). Also `jasperengine-editor scene-diff <old> <new> [--json]`
  (headless, R13/R14), usable as `git difftool` and in CI.

## 6. Design constraints & decisions

- **D1 CLI, not libgit2.**
  - Git LFS locking and LFS smudge exist only in the `git-lfs` CLI; libgit2 has neither.
  - SVN is CLI anyway.
  - The CLI picks up the user's credential helpers, SSH config, hooks and `safe.directory`
    without code from us.
  - libgit2 (GPLv2 with linking exception) would be legal to link, but it adds a large native
    dependency on three platforms and still needs the CLI for LFS.
  - Process cost (≈5–20 ms per call) is off the main thread and bounded by the poll cadence.
- **D2 Layout.**
  - Core: `editor/vcs/` (`IVcsProvider.h`, `VcsTypes.h`, `ProcessExec`, `VcsStatusPoller`,
    `VcsService` owning the active provider, `GitProvider`, `SvnProvider`,
    `VcsPathKey.h`).
  - Scene YAML: `editor/vcs/scene/` (`SceneYamlModel`, `SceneDiff`, `SceneMerge`), which depends
    only on yaml-cpp and `StreamMigrations`.
  - UI: `editor/window/vcs/` (`VcsCommitWindow`, `VcsHistoryWindow`, `SceneDiffWindow`,
    `VcsConflictsWindow`, `VcsOverlay.h`).
  - Commands: `editor/command/type/{RevertFilesCmd, RevertToBaselineCmd}`.
  - Settings: project `editor.vcs.{provider,lfs,lock_scenes}`; user
    `editor.vcs.{git_path,svn_path,lock_on_edit,poll_seconds,lock_poll_seconds,auto_fetch_minutes(0=off),commit_and_push}`.
- **D3 Threading.**
  - `VcsService` runs the poller thread, plus one worker for user operations (S06 background
    lane, serialised: one VCS process for user ops at a time).
  - Every UI action is async with a completion callback on the main thread.
  - A user op finishing wakes the poller.
- **D4 Status flags, not one enum.** UI precedence is fixed in `VcsOverlay.h`, and providers
  never collapse states.
- **D5 Baseline = HEAD (git) / BASE (svn).** The index is not the baseline: our users do not stage
  outside the editor in the common case, and HEAD matches "what is committed".
- **D6 Sketch:**
  ```cpp
  namespace jasperengine::editor::vcs {
  struct ProcessSpec { fs::path exe; std::vector<std::string> args; fs::path cwd;
                       std::vector<std::pair<std::string,std::string>> env; std::string stdinData;
                       int timeoutMs = 30000; size_t maxOutputBytes = 64u << 20; const CancelToken* cancel = nullptr; };
  struct ProcessResult { int exitCode = -1; std::string out, err; bool timedOut = false, truncated = false, spawnFailed = false; };
  ProcessResult runProcess(const ProcessSpec&);
  class IVcsProvider { public: virtual ~IVcsProvider() = default;
    virtual VcsCaps capabilities() const = 0;
    virtual VcsResult status(VcsSnapshot& out, StatusDepth depth) = 0;   // Fast | WithLocksAndRemote | WithIgnored
    virtual VcsResult baseContent(const RepoPath&, std::string_view rev, std::string& out) = 0;
    virtual VcsResult stage(std::span<const RepoPath>) = 0; virtual VcsResult unstage(std::span<const RepoPath>) = 0;
    virtual VcsResult commit(std::span<const RepoPath>, std::string_view message, std::string& revOut) = 0;
    virtual VcsResult revert(std::span<const RepoPath>) = 0;
    virtual VcsResult log(const RepoPath* path, int limit, std::vector<VcsLogEntry>& out) = 0;
    virtual VcsResult lock(std::span<const RepoPath>) = 0; virtual VcsResult unlock(std::span<const RepoPath>, bool force) = 0;
    virtual VcsResult fetch() { return VcsResult::unsupported(); } /* pull, push likewise */ };
  }
  ```
- **D7 Smart merge scope** is scenes and prefabs only (R17–R19). Materials, `project.yaml` and
  meta files use git's text merge, which works well enough because they are small key/value
  files written in stable order.
- **D8 Hosts in tests.** Git LFS locks need a lock API server. We ship
  `tools/vcs-tests/fake_lfs_lock_server.py` (stdlib `http.server`, ≈150 lines). It implements
  `POST /locks`, `POST /locks/verify`, `GET /locks` and `POST /locks/:id/unlock` for two configured
  users. It runs only in tests, with `lfs.url` pointing at `127.0.0.1`. SVN uses `svnadmin create`
  plus `file://`, which supports locks natively.

## 7. Acceptance criteria

All gtest cases are in `jasperengine-editor-tests`, `editor/tests/vcs/`, and run in
`docker/linux.Dockerfile`. That image gets `git-lfs subversion`; it already has `git` (`:8`).
MCP tests are in `tools/mcp/tests/test_vcs.py`. Each test builds its repository in a `TempDir`.

- **AC1** `ProcessExec.ArgumentsReachChildVerbatim`: args `a b`, `"q"`, `$HOME`, `` `x` ``,
  `;rm -rf ~`, `-n`, a trailing backslash and UTF-8 `ñ` echo back byte-exact through a helper
  binary (POSIX + Windows CI job). Port of `VCSCommandExecutorTests` (verbatim args, output
  written just before exit, env overrides, inherited env).
- **AC2** `ProcessExec.TimeoutKillsTree`: a child that sleeps and forks a grandchild is gone
  (both pids) ≤ 3 s after a 500 ms timeout, and `timedOut` is set. `ProcessExec.StdinIsNull`: a
  child reading stdin gets EOF at once. `ProcessExec.OutputCap`: 100 MiB of output comes back
  `truncated` and memory stays ≤ cap + 1 MiB.
- **AC3** `ProcessExec.NoProjectDirHijack`: a `git` script placed in the cwd and a relative
  `PATH` entry is not executed (a marker file is never created).
- **AC4** Port of `VCSStatusPollerTests`: 20 wakes within 100 ms produce ≤ 2 polls; Stop during a
  poll joins; an exception in a poll is logged and the next poll runs.
- **AC5** `GitProvider.StatusPorcelainV2`: in a temp repo with tracked-modified, staged-added,
  untracked, deleted, renamed, ignored, a path with spaces, a newline in a filename, and a
  leading `-`, every entry maps to the expected flags. `branchInfo` reports ahead 1 / behind 2
  against a local bare upstream.
- **AC6** `GitProvider.CommitOnlySelected`: of modified A, B (B pre-staged) and untracked C,
  committing [A, C] with the message `-m "x"; $(touch pwn)` gives a commit containing exactly A
  and C with that message verbatim. B stays staged and no `pwn` file exists.
- **AC7** `GitProvider.FsmonitorIgnored`: a repo whose `.git/config` sets `core.fsmonitor` to a
  script that writes a marker: after `status`, `log` and `diff`, the marker does not exist.
- **AC8** `GitLfsLocks.TwoUsers` (fake server, D8):
  - user A locks `hero.fbx` and A's snapshot shows LockedByMe;
  - user B's clone shows LockedByOther with owner A after the slow poll or a `refresh`;
  - B `unlock` without force fails; with force it succeeds;
  - zero lock-server requests happen during 30 s of idle fast polls.
- **AC9** `SvnProvider.EndToEnd` (`file://` repo):
  - add, modify, conflict (two working copies), `needs-lock` lock/unlock by two users, log,
    `cat -r BASE` and revert;
  - each maps to the expected flags and results.
- **AC10** `RevertFilesCmd.UndoRedo`:
  - revert a modified `.png` + `.meta` and an open dirty scene (confirmation auto-accepted);
  - the files match HEAD and the scene reloads;
  - undo restores byte-identical modified content; redo matches HEAD again;
  - the backup dir is removed at project close.
- **AC11** Port of `SceneDiffTests` to our YAML: align across reordering; added/removed/modified
  properties; entity addition/removal; reparent incl. to/from root; unchanged parent is no change;
  CRLF input makes no false change; GUID is not mistaken for id. Also new cases:
  - `IgnoresDerivedTransformKeys`;
  - `KeyedScriptProperties`: reordering the script properties is not a change; editing `speed`
    gives exactly one property diff at `script.scripts[lua:Enemy.lua].properties[speed].value`;
  - `MigratesBaseline`: a v0 baseline against a vN current shows only real edits;
  - `PrefabMembers` on `tools/fixtures/prefab-runtime/prefabs/Enemy.prefab`.
- **AC12** `RevertToBaseline.*`: property, component and entity revert (Removed → re-created
  with its id; Added → deleted; Reparented → restored). Each is one undo step, and undo returns to
  the pre-revert encoding byte for byte. A prefab-instance member property revert leaves
  `prefabOverridesOf` consistent with a manual revert.
- **AC13** `SceneMerge.*`:
  - non-overlapping edits on two entities merge cleanly;
  - same property, different values → 1 conflict;
  - both sides add id 1050 → theirs renumbered to the max+1 id, and an `EntityReference` to it is
    remapped;
  - `nextEntity` takes the max;
  - delete vs modify → a conflict;
  - the merged output re-encodes through load+save with no diff (`scene-dump` round trip).
- **AC14** `tools/vcs-tests/merge_driver_test.sh` (in docker; script and fixtures only):
  - two branches edit different entities of a fixture scene; with R22 configured, `git merge`
    exits 0 and the scene loads (`jasperengine-editor scene-dump`) with both edits;
  - a same-property edit exits non-zero and leaves a loadable file and a `.conflicts.yaml`;
  - without the driver configured, the merge falls back to text (documents the git behaviour).
- **AC15** `VersionControlMetadata.*`:
  - a new project gets the LFS and `lockable` lines; an existing project without `editor.vcs.lfs`
    gets none;
  - a user-authored (marker-less) `.gitattributes` is untouched;
  - `git check-attr` confirms `filter=lfs` on `.png` and not on `.scene`/`.meta`.
- **AC16** `Stream.DerivedTransformNotWritten`:
  - a saved scene has no `modelMatrix`/`worldPosition`;
  - loading an old fixture with them and re-saving drops them;
  - world matrices after load equal those of the pre-change build for all `tools/fixtures/*`
    scenes (compared via `scene-dump`, epsilon 1e-5);
  - the format version is bumped with a migration fixture.
- **AC17** `test_vcs.py` (MCP):
  - `vcs_status` lists a modified scene;

  - `vcs_revert` without `confirm: true` is refused;
  - `vcs_push` without confirm is refused;

  - `rev: "--output=/tmp/x"` is refused;

- **AC18** Performance (`editor/tests/vcs/VcsBench`, CI thresholds):
  - poll of a generated 10k-file repo ≤ 400 ms;
  - snapshot swap ≤ 1 ms at 20k entries;
  - 2,000-entity diff ≤ 150 ms;
  - 0 process spawns on the main thread after a scripted edit, refresh, log, diff and commit

    thread).
- **AC19** Manual (Linux and Windows, documented in `docs/editor/version-control.md`):

  - "Revert to Baseline" clears both and Ctrl+Z brings them back;

  - a second clone sees the red lock and the read-only Inspector banner;
  - commit two files with "Commit and Push" to a local bare remote; History shows the commit.

## 9. Risks & defaults

- **Lockable non-LFS scenes.** `git lfs lock` on a file that is not an LFS object depends on the
  server; the fake server accepts it, and hosts vary. Default: `lock_scenes` is off, and the
  setting's tooltip says so.
- **Untrusted repositories run code through git config** (fsmonitor, pager, ext-diff, textconv,
  hooks on commit). Default: R4 overrides cover read paths. Commit hooks run, as in any git
  client. `safe.directory` stays git's job.
- **Smart-merge correctness is the biggest risk.** A wrong auto-merge silently corrupts scenes.
  Defaults:
  - The driver is opt-in (R22).
  - Every merged output is round-tripped through `SceneYamlModel` before it is written; on a parse
    failure the driver exits 2.
  - Unknown keyed-sequence types merge as whole values (a conflict if both sides changed).
- **R20 changes every saved scene once** (a one-time diff of removed derived keys). Default: land
  it in its own commit, and call it out in release notes; the migration is lossless.
- **Credential prompts.** GUI credential helpers (GCM) may still pop a window, which is fine. A
  terminal prompt cannot happen (no tty, `GIT_TERMINAL_PROMPT=0`). Missing credentials surface as
  an error after the network timeout. Default: 300 s, cancellable from the progress UI.
- **Large binary base content** (`git cat-file` on an LFS pointer returns the pointer). Default:
  only scenes, prefabs and text files are diffed. Binary rows offer "Open in External Tool" only.
- **Windows path case.** Snapshot keys are compared case-insensitively on Windows and macOS (the
  `:(icase)` pathspec for log, as theirs does).

## Deviations

- **MCP tool names** (R33, AC17). The S31 conventions gate (`tools/mcp/tests/test_tool_conventions.py`)
  requires verb-first names, so the tools are `get_vcs_status` (`vcs_status`), `diff_file`
  (`vcs_diff`), `get_vcs_log` (`vcs_log`), `diff_scene` (`scene_diff`), `revert_to_baseline`
  (`scene_diff_revert`), `lock_files` / `unlock_files` (`vcs_lock` / `vcs_unlock`), `commit_files`
  (`vcs_commit`), `revert_files` (`vcs_revert`) and one `sync_remote` with `action`
  fetch / pull / push (`vcs_fetch/pull/push`: the gate has no fetch/pull/push verb, and one tool
  keeps the group small), in the tool group `vcs` (hidden until `tool_groups` enables it). The
  parameters are the spec's; the remote operations are jobs (`wait`, `timeout_seconds`). `get_vcs_status` with `refresh: true` also looks for a repository again
  when there was none (a `git init` after the project opened). AC17's "unsaved
  `set_component_value` edit" is a `set_transform` edit (the editor has no `set_component_value`).
- **Agent guide**: no line of its own. With S19 merged the guide is within a few bytes of its
  16,384 (the generated tool-groups line names `vcs`); the reference is `jasper://docs/vcs`
  (docs/mcp/guide/vcs.md), listed by `jasper://docs` and named in `get_vcs_status`' description.
- **Hierarchy glyphs** (R27) of GameObject rows are drawn after the name, not before it: before
  the name sit the prefab icon and the variant badge, which the glyph would overlap at narrow
  widths. The scene row and the Project window follow R27.
- **Document-level derived keys** (R14). Besides `kDerivedKeys` (the transform's world values),
  the diff ignores the document keys the encoder recomputes on every save (`maxValues`,
  `shaderKeys`, `formatVersion` / `version`), which would otherwise show a change on every
  re-save of an unchanged scene. The Derived flag of the reflection tables (S08) marks the
  per-component ones (light `worldDirection`, bone `offsetMatrix`, ...), so the table is
  `kDerivedKeys` plus every `Derived` field.
- **Prefab instance members** (R14): a member's override is listed under the member GameObject
  (`prefab_member: true`, its instance root and registry id), not under the instance root's
  `prefabInstance` component, so Revert to Baseline acts on the member as the Inspector's Revert
  does (`PrefabOverrideCmd`).
- **Lock on edit** (R12) runs from S24's history hook, which reports an edit after it happened:
  the question comes right after the first edit that dirties a lockable scene or prefab (or the
  first import-settings edit of a lockable asset, `SetAssetMetaCmd`), and Cancel (or "Undo the
  Edit" for a file locked by someone else) undoes that edit, which leaves the document as it was.
- **AC16 goldens**: the build before R20 has no `scene-dump --world` (this stream adds it), so
  `editor/tests/fixtures/vcs/world/` was captured from this branch before the R20 commit; the
  fixtures upstream added later (html-ui, pose-animation, AllComponents' new GameObjects) were
  captured from the merged tree with R20's load path switched off (no key removal in the
  migration, no post-decode update), which is what the older build did on load.
- **R26 encode budget** makes 10 ms a switch (over it, the tracker diffs the saved file:
  "Showing saved changes"). A 2,000-GameObject encode took ~30 ms on the benchmark server.
- **R20 format versions**: scene 3 -> 4 and prefab 5 -> 6 (`Prefab::FILE_VERSION` 6); prefab files
  are written again (needsUpgrade) the next time a scene using them is saved. The reflection
  table gains a `NotWritten` flag on the six transform fields: left out of documents (encodes
  inside a `reflect::DocumentEncodeScope`: `Stream::encodeSceneProject`,
  `Project::encodePrefabNode`, `Project::encodePrefabStage`), read when present; the in-memory
  encodes (undo snapshots, the clipboard) keep them, since a restore may need them before the
  next transform pass (a model's layout switch undone under a reparent does). The Transform's
  post-decode sets `needUpdate`, so the first transform pass computes them. That pass runs when a Scene view draws, so what reads world values in Edit mode before it (Lua `getWorldPosition`, MCP, picking, bounds, a navigation bake) saw zeros right after a load (BF7: `test_pose_runtime.py`): the world values are now computed where decoded transforms arrive (`editor/util/WorldTransforms.h`: a scene's load, a decode, a Prefab registry, an instantiated Prefab), with `updateWorldTransforms` (engine `TransformPropagation.h`, the math `RenderSystem::updateTransform` uses). A stream that bumps the scene version too (S18) renumbers on merge.
- **Test hooks**: `ProviderConfig::svnGlobalArgs` (the SVN tests pass `--username` for two users
  of one `file://` repository) and `VcsSettings::usePathOverride` / `pathOverride` (AC20 runs the
  detection with an empty `PATH`), and `VcsSettings::pollMilliseconds` /
  `lockPollMilliseconds` (sub-second cadences for AC8). None is reachable from the UI or MCP.
- **Windows**: the process runner's Windows path (CreateProcessW with `QuoteArgument`, a job
  object, an explicit handle list) is built by the Windows CI job; the gate of this stream ran on
  Linux (the build servers have no Windows host), so AC1's Windows half and AC19 on Windows are
  for the integrator's Windows run.
