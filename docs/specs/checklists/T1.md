# T1 manual check (AC27, AC38)

Run in an isolated editor on a scratch project with a Terrain of a few hundred units. Each step names
what to see. Screenshots and numbers go with the record of the run, not into the repository. Nothing
here can run on the build host: it has no tablet, no Windows, no macOS and no GPU.

## Pen pressure (R37)

Once on each of Windows (Windows Ink), macOS (a Wacom or Sidecar pencil), Linux X11 and a Wayland
desktop (the editor runs through XWayland there):

1. Terrain window, Raise. The Brushes section shows Pressure Strength on and Pressure Size off.
2. Drag with the pen, pressing lightly, then hard: the light part rises less. The decal keeps its size.
3. Turn Pressure Size on and Pressure Strength off: the strip narrows where the pen was light and rises
   evenly.
4. Tap the pen without dragging: one stamp lands at full strength, as a mouse click does.
5. Rest the pen on the surface with no pressure and move it: nothing rises after the first tenth of a second.
6. Put the pen down and drag with the mouse: the mouse paints at full strength with either option on.
7. Unplug the tablet and plug it back in with the editor open: step 2 still holds.
8. In Play, a script printing `Input.getPenPressure()` each frame shows the pen's pressure, and -1 once
   the mouse moves.

On a web export, an Android device with a stylus and an iPad with an Apple Pencil, step 8 alone (the
Terrain window is the editor's).

## Budgets on reference hardware (R47-R54)

9. On an idle 8-core desktop in release: `je-bench-terrain --json terrain.json`, then
   `python3 tools/perf/check_bench.py terrain.json`. Record every line in `docs/perf/terrain.md`.
10. The same machine: `JASPER_TEST_PERF_SLACK=1` and `--gtest_filter=TerrainDeltaBench.*` in the editor tests.
11. GPU upload time of a runtime edit on a real GPU per backend (Table 3 of the spec): bytes are exact on
    the host, time is not.
