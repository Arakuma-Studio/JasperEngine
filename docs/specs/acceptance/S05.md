# S05 acceptance note: file watcher and hot reload

What AC21 asks to check by hand on Windows and on macOS (the CI runners and the build servers
are Linux only), and its record. Linux is covered by the automated tests (`FileWatcherTests`
with the inotify and polling backends, `tools/mcp/tests/test_hot_reload.py`).

## Procedure (each of Windows 10/11 and macOS 13+)

1. Open a project with a 2D scene showing a sprite whose texture is `assets/hr/tex.png`.
   The status bar shows *Watching (ReadDirectoryChangesW)* (Windows) or *Watching (FSEvents)*
   (macOS).
2. Open `tex.png` in Paint.NET (Windows) or Preview (macOS), paint it another colour, save.
   Expected: the sprite shows the new colour in under 1 s; the Console has one line,
   `[Hot Reload] Reloaded assets/hr/tex.png (texture, N ms)`. Clicking it selects the file in
   the Project window.
3. Save a `.lua` script attached to a GameObject from VS Code with a new property in its
   `properties` table. Expected: the Inspector shows the new property, no Files Changed prompt.
4. Rename a folder holding textures and a prefab in Explorer / Finder. Expected: the Project
   window follows (the folder under its new name, the selection kept), the prefab's instances
   keep working (its GUID is kept), no `[Hot Reload]` error.
5. On Windows, keep `tex.png` open in the editor (a texture loading) while the image editor
   saves over it: the save succeeds (the editor reads with share-delete).
6. Screenshots of steps 2 and 4 go next to this file (`S05-windows-*.png`, `S05-macos-*.png`).
