Production bug exposed by the better tests

The shader guide explicitly permits project-relative fork paths with an
assets-relative fallback (docs/mcp/guide/shaders.md:166-167). Opening an
existing project installs ShaderManifests' Project::readShaderFile callback;
creating a fresh project did not. Once assets_dir was a distinct directory,
valid project-root shader files could produce empty scene-input metadata
and compile against the wrong requirements.

The minimal real-editor reproduction had both files present and assets_dir
set to assets, yet returned no scenedepth input and failed. The fix installs
the same lazy reader in Project::createProjectInDirectory before loading any
new scene. The existing test_material_variant now covers this configuration
and restores settings afterward; no new test-only production seam was added.
The old reproduction fails and the fixed editor reports reads: [scenedepth].
Relevant logs: tappy-shader-root-repro.log,tappy-shader-root-fixed.log and
8/8 passing scene-input owners on the rebuilt native editor. All five native
CPU targets also pass after this fix.
