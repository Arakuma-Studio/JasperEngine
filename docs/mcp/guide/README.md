# Agent reference docs

Longer references behind the agent guide (`editor/mcp/McpInstructions.cpp`, sent as
`initialize.instructions` and served as `jasper://guide`). They are embedded in the editor at
build time (`CMakeLists.txt` generates `mcp_docs.h`; `editor/mcp/tools/DocsTools.cpp` serves
them), so a new file here becomes `jasper://docs/<file name>` after a rebuild. This README is
not served; `jasper://docs` lists the served documents. The guide refers to them by these URIs:

| File | Resource | Contents |
|---|---|---|
| [lua-api.md](lua-api.md) | `jasper://docs/lua-api` | Lua script structure, property types, events, every bound class used in gameplay, enums, pitfalls (checked against `engine/core/script/binding/*`) |
| [cpp-scripting.md](cpp-scripting.md) | `jasper://docs/cpp-scripting` | C++ script kinds, DPROPERTY, event macros, includes, script dirs, ProjectBuild.cmake |
| [physics.md](physics.md) | `jasper://docs/physics` | bodies and colliders, mass and density, forces, teleporting, layers, ray casts |
| [shaders.md](shaders.md) | `jasper://docs/shaders` | forking built-in shaders, editing rules, the custom uniform block |
| [prefabs.md](prefabs.md) | `jasper://docs/prefabs` | overrides, Apply/Revert, Prefab Mode, variants, Instantiate/Destroy, the build's prefabs |
| [html-ui.md](html-ui.md) | `jasper://docs/html-ui` | HTML/CSS game UI (UI Document component), 16 sections: the model and where Chromium parity stops, quick start with the MCP loop, files, HTML, CSS, the Lua element API, data binding, `anime`, images/SVG/Lottie/fonts/icons and imports, input and pointer pass-through, responsive layout, diagnostics / `check --ui` / `inspect_ui` / `assert_ui`, web habits to change, the examples, performance, C++. Its html/css/lua blocks are checked by `tools/mcp/tests/test_html_ui_docs.py` |
| [html-ui-support.md](html-ui-support.md) | `jasper://docs/html-ui-support` | the HTML/CSS support matrix: every element, attribute, CSS property, value, function, unit, selector, at-rule and media feature with its status and replacement, and every diagnostic code. Generated by `tools/mcp/gen_html_ui_support.py` from `jasperengine-editor ui-support`: do not edit by hand |
| [html-ui-effects.md](html-ui-effects.md) | `jasper://docs/html-ui-effects` | the HTML UI effect catalogue: every built-in `effect()` by category with its kind, cost, parameters (type, default, range), a CSS example and its thumbnail (`img/effects/<name>.png`, not served). Generated by `tools/htmlui/gen_effects_docs.py` from the effects' manifests: do not edit by hand |
| [../../unity-glossary.md](../../unity-glossary.md) | `jasper://docs/unity-glossary` | Unity term to engine name tables |

The HTML/CSS UI examples (`html-ui-examples/`: one folder per example and `examples.json`) are
embedded separately: every project gets them in `.jasperengine/engine-api/html-ui-examples/`, and
they are served as `jasper://examples/html-ui`.

Keep these in sync with the engine: a name in them must exist in the bindings or headers.
